# 展示ブースの体験モード(Kobe Calling)

来場者が**実物のARグラス**を掛け、走らずに「走っているときの見え方」を体験するモード。
小さなブースで回すことを前提に、**立ったまま**(主)と**数歩あるく**(副)の2つを用意した。

アバター・HUD・色・オーラ・GPSロストのフェードは**本番の実装そのもの**で、偽物なのは入力
(ペース・距離・GPS精度)だけ。デモの走行は履歴・CSV・HealthKit に残らない。

| | 立ったまま (`standing`) | 数歩あるく (`walking`) |
|---|---|---|
| 来場者 | その場に立つ | ブース内を数歩あるく・向きを変える |
| アバターを動かすもの | 台本(`BoothDemoScript`) | 来場者自身の移動(ARKit) |
| 長さ | カウントダウン約4秒 + 65秒、ゴールで自動終了 | カウントダウン + 60秒 |
| 目標ペース(既定) | 12 km/h(5:00/km) | 6 km/h |
| GPSロスト判定 | ON(台本で発動させる) | OFF(屋内でGPSが無いため) |
| 見せられるもの | ジャスト(緑)・遅れ(橙→赤+オーラ+HUD赤)・追い抜き(青寄り)・F-09慣性→F-10フェード+赤字警告→復帰・ゴールライン | 3m前方の追従・旋回への追従(最大45°/s) |

## 立ったままの台本

時刻はカウントダウンの START から。実装は [BoothDemoScript.cs](../Assets/_Project/Scripts/BoothDemoScript.cs)、
本番の判定と噛み合っていることは `Tests/UnitTests/BoothDemoScriptTests.cs` と E2E(Step 7)で縛っている。

| 秒 | 区間 | アバター | HUD |
|---|---|---|---|
| 0–10 | ジャスト | 3.0m前方・緑 | ペース緑、時間・距離が進む |
| 10–22 | 遅れ | 4秒かけて約9m先へ離れる → 赤・足元からオーラ・減速 | ペース赤 |
| 22–28 | 追い上げ | 3.0mへ戻る | ペース緑 |
| 28–35 | 追い抜き | 1.2mまで寄る → 緑から青寄り・脚が速まる | ペース緑 |
| 35–40 | 戻る | 3.0mへ | |
| 40–49 | GPSロスト | 5秒の慣性移動 → 1秒でフェードアウト → 非表示 | 下部に赤字「GPS信号を探索中」・距離が止まる |
| 49–53 | 復帰 | 光の粒が集まって再表示(1.5秒) | 距離が追いつく |
| 53–65 | 最後の直線 | ゴールラインが見えてくる | |
| 65 | ゴール | 停止 | |

立ったままではユーザーとアバターの距離が変わらないので、遅れ・追い抜きの区間だけ
アバターの追従位置を前後へずらしている(`AvatarEngine.SetPresentationLeadOffset`)。
色やオーラの判定基準の 3.0m はずらさないので、ずらした分がそのまま本番の判定に「遅れ」「追い抜き」として出る。

- 追い抜きで「右へ譲る」本番の動作は使わない。1.2m先で0.8m横へ出るとグラスの水平画角から外れる。
- 遅れは9.0mで止める。10m離れると本番の「離隔待機(手招き)」に切り替わってしまう。

## ブースの準備

1. **iPhoneは胸の前に固定する**(チェストマウント等。カメラを前へ向ける)。グラスに映るのは
   iPhoneのカメラ視点で、iOSからはグラスの頭の向きを取れない([XREAL_ONE_INTEGRATION.md](XREAL_ONE_INTEGRATION.md))。
   手で持つと、iPhoneの向きがそのまま映像の向きになってしまう。
2. **来場者はブースの開けた方向を向いて始める**。アバターは前方3m(遅れ区間は約9m)に立つ。
   壁を向いて始めると、壁の中にアバターが立って見える(光学シースルーなので壁で隠れない)。
3. グラスは XREAL One、画面モードは **Follow**(Anchor は頭の補正が二重になる)。
4. 歩行モードは床が見えている場所で。アバターの接地は LiDAR / 平面検出が頼り。

## 起動の仕方

- **iPhone(本番の流れ)**: Swiftの体験モード画面から `StartBoothDemo {"mode":"standing"|"walking"}` を送る。
  中断は `StopBoothDemo`。進行は `BoothDemoProgress`、終了は `BoothDemoEnded` で返る
  (契約は [SWIFT_INTEGRATION.md](../SWIFT_INTEGRATION.md))。**Swift側の画面は未実装**(下記)。
- **Windowsノート+グラス(Macが無いときの予備・立ったままのみ)**: XREAL One をノートにUSB-Cで挿し、
  Unityエディタで `Tools → AR Pacesetter → Booth Demo → Start Standing`。Game ビューをグラス側の画面へ
  出して最大化する。黒はグラスでは透明になる。来場者の動きは追えない(ARKitが無い)ので歩行モードは使えない。

## 何が残らないか

デモで始めた走行(`ARSessionManagerBridge.IsPresentationSession`)は次を止める。

- 走行履歴(`SessionDataStore`)・中断スナップショット — ゴーストの候補や統計が来場者で埋まらない
- 走行ログCSV(`RunLogs/`) — 合成値で §11.2 の評価に使えず、来場者の数だけ溜まる
- `SessionEnded` — Swiftが受けるとHealthKitへワークアウトを保存するため。代わりに `BoothDemoEnded`
- デモ中に届いたSwiftの `UpdateMetrics` — 屋内の悪い精度が混ざると、台本と無関係な時刻にアバターが消える
