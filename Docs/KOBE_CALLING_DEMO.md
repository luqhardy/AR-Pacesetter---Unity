# 展示ブースの体験モード(Kobe Calling)

来場者が**実物のARグラス**を掛け、走らずに「走っているときの見え方」を体験するモード。
小さなブースで回すことを前提に、**立ったまま**(主)と**数歩あるく**(副)の2つを用意した。

アバター・HUD・色・オーラは**本番の実装そのもの**で、偽物なのは入力
(ペース・距離)だけ。デモの走行は履歴・CSV・HealthKit に残らない。

**アバターは体験中に一度も消さない**(2026-10-07 チーム判断)。以前の台本は GPSロスト
(F-09 慣性 → F-10 フェードアウト → 赤字警告)を見せていたが、来場者には「消えた=壊れた」に見えた。
体験モードでは GPSロスト判定を止め、アバターを来場者の正面に保つ。**走行本番の F-10 は仕様どおり**。

| | 立ったまま (`standing`) | 数歩あるく (`walking`) |
|---|---|---|
| 来場者 | その場に立つ | ブース内を数歩あるく・向きを変える |
| アバターを動かすもの | 台本(`BoothDemoScript`) | 来場者自身の移動(ARKit) |
| 長さ | カウントダウン約4秒 + 52秒、ゴールで自動終了 | カウントダウン + 60秒 |
| 目標ペース(既定) | 12 km/h(5:00/km) | 6 km/h |
| GPSロスト判定 | OFF(アバターを消さない) | OFF(同上・屋内でGPSが無い) |
| アバターの向き | 来場者の正面(体の向きを変えると0.5秒ほどで回り込む) | 同左 |
| アバターの身長 | 145cm(3.0m先でグラスに頭から足元まで収まる) | 同左 |
| 見せられるもの | ジャスト(緑)・遅れ(橙→赤+オーラ+HUD赤)・追い抜き(青寄り)・ゴールライン | 3m前方の追従・旋回への追従(最大45°/s) |

## 立ったままの台本

時刻はカウントダウンの START から。実装は [BoothDemoScript.cs](../Assets/_Project/Scripts/BoothDemoScript.cs)、
本番の判定と噛み合っていることは `Tests/UnitTests/BoothDemoScriptTests.cs` と E2E(Step 7)で縛っている。

| 秒 | 区間 | アバター | HUD |
|---|---|---|---|
| 0–10 | ジャスト | 3.0m前方・緑 | ペース緑、時間・距離が進む |
| 10–22 | 遅れ | 4秒かけて約9m先へ離れる → 赤・足元からオーラ・減速 | ペース赤 |
| 22–28 | 追い上げ | 3.0mへ戻る | ペース緑 |
| 28–35 | 追い抜き | 1.2mまで寄る → 緑から青寄り・脚が速まる | ペース緑 |
| 35–40 | 戻る | 3.0mへ | |
| 40–52 | 最後の直線 | ゴールラインが見えてくる | |
| 52 | ゴール | 停止 | |

立ったままではユーザーとアバターの距離が変わらないので、遅れ・追い抜きの区間だけ
アバターの追従位置を前後へずらしている(`AvatarEngine.SetPresentationLeadOffset`)。
色やオーラの判定基準の 3.0m はずらさないので、ずらした分がそのまま本番の判定に「遅れ」「追い抜き」として出る。

- 追い抜きで「右へ譲る」本番の動作は使わない。1.2m先で0.8m横へ出るとグラスの水平画角から外れる。
- 遅れは9.0mで止める。10m離れると本番の「離隔待機(手招き)」に切り替わってしまう。
- **向きは iPhone(=胸)の正面から取る**(`AvatarEngine.SetPresentationFollowsView`)。本番の走行は
  移動の向きを使い視線は使わない(§4.1 Gaze Lock — 走行中の酔い防止)が、立ったままでは移動が無く、
  体の向きを変えるとアバターが部屋に置き去りになって視野から消えた。4°以上ずれたら180°/sで向き直り
  (90°で約0.5秒)、位置の平滑も速める。**グラスの視点(`GlassViewRig`)も同じ向きを使う**。
  - 2026-10-09 実機「体を傾けてもすぐ反応しない」: 以前は不感帯12°・走行と同じ45°/sで、90°に約2.5秒。
    さらにグラスの視点だけは走行用の追跡方位(開始時の向き)のままで、アバターだけが回り込んでいた
  - 合成のGPS座標は送らない(距離・ペースだけ)。送ると追跡側が「北へ進む」fixを方位に使い、
    来場者が15cm揺れただけでその方位をARの任意の向きへ結び付けてしまう
- **アバターは145cm**(`BoothDemoScript.AvatarHeightCm`)。XREAL One の垂直画角は約25.8°で、3.0m先の足元は
  眼高1.55mから27°下にある。175cmでは全身に31.1°要り収まらない(俯角の上限15°)。145cmなら俯角14.6°で
  頭から足元まで(遅れのときのオーラも)見える。距離(3.8mなら175cmでも収まる)ではなく大きさを譲ったのは、
  台本の距離(遅れ9m・離隔待機10m)をそのまま使えるため。グラスの俯角は**実際に置いている距離**で決めるので、
  9m先へ離れても頭が視野の上へ切れない。ユニットテストで縛っている

## ブースの準備

1. **iPhoneは胸の前に固定する**(チェストマウント等。カメラを前へ向ける)。グラスに映るのは
   iPhoneのカメラ視点で、iOSからはグラスの頭の向きを取れない([XREAL_ONE_INTEGRATION.md](XREAL_ONE_INTEGRATION.md))。
   手で持つと、iPhoneの向きがそのまま映像の向きになってしまう。
2. **来場者はブースの開けた方向を向いて始める**。アバターは前方3m(遅れ区間は約9m)に立つ。
   壁を向いて始めると、壁の中にアバターが立って見える(光学シースルーなので壁で隠れない)。
3. グラスは XREAL One、画面モードは **Follow**(Anchor は頭の補正が二重になる)。
4. 歩行モードは床が見えている場所で。アバターの接地は LiDAR / 平面検出が頼り。

## 起動の仕方

- **iPhone(本番の流れ)**: ホームのメニュー → **体験モード(展示)**(`BoothDemoView`)。スタッフが操作する。
  1. グラスを挿す(上部のチップが「グラス接続中」になる)。モードと「開始までの猶予」(既定10秒)を選ぶ
     - **「ミラーリング中」と出たら体験に使えない** — グラスにiPhoneの画面(この操作パネル・カメラ映像)が
       そのまま映っている。iOSがグラス専用の画面を作っていない状態(下の「グラスがミラーリングになる」)
  2. **開始** → 猶予のあいだに iPhone を来場者の胸のマウントへ入れる → グラスで 3・2・1・START
  3. 実行中は「いまの区間」と、来場者へかける一言(何が見えているか)を大きく出す。残り秒数と区間の一覧つき
  4. ゴールで自動終了 →「次の方を開始」。途中で止めるときは **中断**
  - 画面は体験モード中ずっと自動ロックしない(消えるとグラスへの出力も止まる)
  - 送るのは `StartBoothDemo {"mode":"standing"|"walking"}` / `StopBoothDemo`、受けるのは `BoothDemoProgress` / `BoothDemoEnded`
    (契約は [SWIFT_INTEGRATION.md](../SWIFT_INTEGRATION.md))。走行用の CoreLocation / HealthKit は起動しない
- **Windowsノート+グラス(Macが無いときの予備・立ったままのみ)**: XREAL One をノートにUSB-Cで挿し、
  Unityエディタで `Tools → AR Pacesetter → Booth Demo → Start Standing`。Game ビューをグラス側の画面へ
  出して最大化する。黒はグラスでは透明になる。来場者の動きは追えない(ARKitが無い)ので歩行モードは使えない。

## グラスがミラーリングになる

グラスに iPhone の画面がそのまま映るのは、iOS が外部ディスプレイ用のシーンを作っていないとき。
2026-10-07 の実機で発生し、Info.plist にシーン定義を静的に書く形へ直した
([SWIFT_INTEGRATION.md](../SWIFT_INTEGRATION.md) ③')。直ったかは次で確かめる:

- 体験モード画面のチップが「グラス接続中」になる(「ミラーリング中」ではない)
- グラスにボタンやカメラ映像が出ず、アバターとHUDだけが現実に重なって見える
- Xcode のコンソールに `[ExternalDisplay] シーン構成の要求: role=UIWindowSceneSessionRoleExternalDisplayNonInteractive`
  と `ARグラス接続 — ARビューをグラスへ出力します` が出る

なお通常の走行フローの準備画面は、ARグラス行を**タップすると実接続が無くても1.5秒後に「接続済み」になる**。
ミラーリングに気づきにくいのはこのため。

## 何が残らないか

デモで始めた走行(`ARSessionManagerBridge.IsPresentationSession`)は次を止める。

- 走行履歴(`SessionDataStore`)・中断スナップショット — ゴーストの候補や統計が来場者で埋まらない
- 走行ログCSV(`RunLogs/`) — 合成値で §11.2 の評価に使えず、来場者の数だけ溜まる
- `SessionEnded` — Swiftが受けるとHealthKitへワークアウトを保存するため。代わりに `BoothDemoEnded`
- デモ中に届いたSwiftの `UpdateMetrics` — 屋内の悪い精度を台本へ混ぜない
