# 設定ペースでの自走 (2026-10-12)

通常走行の既定は `AvatarEngine.PacingMotion.TargetSpeed`。カウントダウン終了後、
設定ペースを `1000 / (分/km × 60)` m/s に変換し、毎フレーム `速度 × deltaTime` だけ
アバターのルートを水平移動する。3mは開始時のリードであり、走行中の固定距離ではない。
Swiftの走行設定は従来どおり StartSession の km/h で受け取り、既存の変換を使う。
走行画面の「アバター速度」±操作から `SetTargetSpeed` (1〜30 km/h) を送信する。
Unityの `TargetSpeedUpdated` 応答を「設定済み」に表示する。手動変更はゴースト再生を解除する。

- 走者が速ければ追い抜ける。走者が遅くなればアバターが追い抜き返す。
- 自走中のエラスティック減速・スプリント倍率は使わず、指定ペースを保つ。
- 前方かつ水平距離10m以上で待機し、7m以内または走者が待機時の進行軸で追い抜いたら再開する。
  待機判定の軸は待機開始時に固定し、横移動を接近と誤認しない。走行方位の更新は待機中も継続。
  待機中は走行方向を向き、再開前に向きが5度以内に揃うまで停止する。
- 障害物・終了時は停止。GPSロスト時は既存の慣性移動/FSMを使い、復帰時に3mへ戻さない。
- 展示デモ (`PresentationFollowsView`) は既存アンカー追従。明示的な `FollowUser` も保持。
- 方向は走者の融合済み移動方位を使用し、45度/秒で旋回。独立したトラック経路の走行ではない。
  コーナーでは走者とアバターが別の経路を通り得るため、この段階は直線で検証する。

## 実機確認

1. Unityを再エクスポートし、Xcodeで `ios/ARRunner.xcworkspace` の `AR_Runner_UI` を実機へビルド。
2. 展示体験ではなく通常走行で目標ペースを設定。5:00/km (12km/h) なら3.33m/s。
3. カウントダウン後、走者より速ければ前方の距離が増えることを確認。
4. 走者がアバターより速く進み追い抜く。減速し、アバターが追い抜き返すことを確認。
5. 別の設定ペースで再スタートして実移動速度が変わること、終了で止まることを確認。
6. 前方10mでの待機・再開、GPS喪失と復帰、展示デモも確認。
