# 差し替えアバター(VRM)

「VRChatのアバターを自分の伴走者にしたい」への回答と、その実装。

---

## 1. VRChatのアバターは**そのままでは使えない**

理由は3つあり、どれも回避できない。

| | |
|---|---|
| **VRChatから取り出せない** | アップロード済みアバターは暗号化された `.vrca` アセットバンドルになり、VRChatのパイプラインに紐づく。抽出はToS・著作権の両面で不可 |
| **iOSは実行時のコード読み込みを許さない** | UnityはIL2CPPのAOTでビルドされるため、アセットバンドルはメッシュ・テクスチャを運べても**新しいC#は運べない**。VRC SDKのコンポーネント、Modular Avatar、PhysBones はビルドに存在しないので失われる |
| **シェーダがビルドに無い** | Poiyomi / liltoon 等はアプリに含まれない。参照しても解決されずマテリアルが壊れる |

## 2. 使えるのは **VRM**

BOOTH等で購入したアバターの多くは FBX + テクスチャで配布され、**`.vrm` を同梱しているか、書き出せる**。
VRMはアプリ間で持ち運ぶことを目的に設計された人型アバターの標準形式で、

- **データのみ**(コードを含まない)→ iOSの制約に当たらない
- **ヒューマノイドリグを保証する** → 本アプリのロコモーション(歩行/走行のブレンド)をそのまま当てられる
- UniVRM で**実行時に読み込める**

つまりユーザーへの案内は「VRChatと連携します」ではなく
**「アバターをVRMで書き出して、それを入れてください」**になる。

---

## 3. 実装されているもの / いないもの

| 要素 | 状態 |
|---|---|
| `VrmAvatarPolicy` — 受け入れ判定(依存ゼロ・ユニットテスト12件) | **実装済み** |
| `VrmAvatarLoader.Measure` — モデルの実測(三角形・マテリアル・発光・素の身長) | **実装済み**(UniVRM不要) |
| `VrmAvatarLoader.TryAdopt` — 判定して差し替え、Animator/IK/レンダラー/身長を再配線 | **実装済み**(E2Eで常時検証) |
| `VrmAvatarCatalog` — 同梱 `.vrm` の一覧 | **実装済み** |
| `.vrm` のパース(UniVRM) | **`#if UNIVRM` の中。既定は休眠** |
| ユーザーによるファイル取り込みUI(`AvatarLibraryView`) | **実装済み** — ホーム右上メニュー → アバター |
| ライセンス同意の導線 | **未実装** |

**モデル本体は同梱していない** — ライセンス上、購入者本人が自分のモデルを置く。

## 3.5 端末から取り込む(実装済み)

ホーム右上メニュー → **アバター** → 「.vrm を取り込む」。

1. ファイルアプリ(iCloud/Drive/AirDrop受信先)から `.vrm` を選ぶ
2. Swiftが**セキュリティスコープを開いて** `Documents/Avatars/` へコピーする
   — ピッカーが返すURLはスコープ付きで、そのままではUnityから読めない
3. **絶対パス**をUnityへ渡す(`ImportVrmAvatar`)
4. Unityが計測・判定し、結果を `VrmImportResult` で返す
5. 画面に**断った理由が実測値つきで出る**(例: 142,000三角形 / 上限 70,000)

`.vrm` にシステムのUTIは無いため、拡張子から型を引けなければ任意のデータとして受ける。

> **UniVRM が入っていないビルドでは必ず失敗する**。その場合も無言で失敗せず
> 「UniVRM が未導入のビルドです」と理由を返す。**取り込み機能は後付けできない** —
> UniVRMを含めた再ビルドが要る。

## 4. 同梱アバターの追加手順

1. `.vrm` を **`Assets/StreamingAssets/Avatars/`** へ置く(ファイル名がそのまま表示名)
2. UniVRM を導入する — Package Manager → Add package from git URL:

   ```
   https://github.com/vrm-c/UniVRM.git?path=/Assets/VRMShaders
   https://github.com/vrm-c/UniVRM.git?path=/Assets/UniGLTF
   https://github.com/vrm-c/UniVRM.git?path=/Assets/VRM
   ```

   (VRM 0.x 系。順序どおりに入れる)
3. Player Settings → Scripting Define Symbols へ **`UNIVRM`** を追加
4. 再生して、ログの `[VRM] アバターを差し替えました — …` に実測値が出ることを確認

**`UNIVRM` を外せば即座に元の状態へ戻る。** 既定アバターの動作には一切影響しない。

## 5. 受け入れ基準と、その理由

判定は `VrmAvatarPolicy`。**見た目のために計測を壊さない**ことが目的で、
本アプリはアバターの裏で **ARKit + GPS + 100Hz IMU + CSV書き出し**を回しながら
60fps と **M2P 20ms**(§10)を守らなければならない。

| 条件 | 上限 | 外れたときの扱い |
|---|---|---|
| ヒューマノイドリグ | 必須 | **拒否** — 歩行・走行アニメーションを当てられない |
| 三角形数 | **70,000** | **拒否** — 60fpsとM2Pを守れない |
| マテリアル数 | **8** | **拒否** — SetPass(ドローコール)が増えて描画が間に合わない |
| スキンメッシュ数 | **4** | **拒否** |
| 発光マテリアル | 1枚以上 | **拒否しない。ただし警告**(§7.1のペースシンクロ色が視覚に出ないため) |

> **上限の根拠**: 現在シーンで動いているアバターは **55,320三角形 / マテリアル2枚**(E2E実測)。
> VRChat向けアバターは7万〜20万三角形が珍しくないので、多くはそのままでは通らない。
> 通したい場合はポリゴン削減とマテリアル統合(アトラス化)が要る。

**拒否しても既定アバターは一切触らない** — 断ったついでに表示を壊すのが最悪の失敗なので、
E2Eで「拒否後も表示中のアバターの身長が変わらないこと」を検証している。

---

## 6. ライセンス

BOOTH等のアバターは再配布を禁じ、VRChat以外での利用を制限しているものもある。

- **ユーザーが自分で購入したモデルを自分の端末へ入れる**のは通常問題ない
- **アプリがモデルを同梱・配布・ホストしてはいけない**
- 取り込みUIを作る段階では、利用許諾の確認導線を必ず入れること

## 7. 優先度について

第1期のスコープは F-01〜F-11 で、アバターの差し替えは含まれない。
さらに [XREAL_ONE_INTEGRATION.md](XREAL_ONE_INTEGRATION.md) §4 のとおり、
グラス越しに3.0m前方のアバターは **約0.87mより上しか見えない**(垂直FoV 25.7°)。
胴体だけが見える状態で凝ったモデルを載せても効果は限定的なので、
**F-03の距離の判断が先**。
