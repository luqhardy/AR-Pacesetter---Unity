# XREAL One 統合の基盤 — 調査結果と設計判断

第1期(基本設計書 §1.2)で採用する「iPhone + ARグラス(USB-C有線)」構成のうち、
**グラス側で何が成立し、何が原理的に不可能か**を一次情報で確定させ、
そこから導かれる実装方針を記録する。実装は `GlassViewRig` / `GlassDisplayProfile` /
`GlassOpticsMath` / `HeadPoseMath`(いずれも `Assets/_Project/Scripts/`)。

調査日: 2026-09-16

---

## 1. 確定した事実(一次情報)

| 項目 | 事実 | 出典 |
|---|---|---|
| 画角 | XREAL One = **50°** / One Pro = **57°** | XREAL公式ドキュメント・製品ページ |
| 解像度 | **1920×1080 / 眼** | 同上 |
| リフレッシュレート | 60 / 72 / 90 / 120Hz | XREAL公式ドキュメント |
| 空間処理 | 自社X1チップが**グラス単体で3DoF**を行う。M2P **約3ms @120Hz** | XREAL製品ページ |
| 画面モード | **Anchor**(空間固定)/ **Follow**(視線追従・固定とスムーズ)/ Ultra-Wide / Side View / 3D | XREAL公式チュートリアル・ユーザーガイド |
| 対応ホストOS | **Androidのみ**(BeamPro以降はSamsungフラッグシップのみ継続対応) | XREAL SDK 互換性ページ |
| SDK | XREAL SDK(旧NRSDK)は Unity + **Android Build Support** 前提。**iOS対応の記載は一切無い** | XREAL SDK ドキュメント |
| iPhoneの映像出力 | iPhone 15以降のUSB-Cは **DisplayPort Alt Mode** で最大4K60の外部ディスプレイ出力に対応。Lightning世代(〜iPhone 14)はアダプタ経由1080pまでで、グラスのDP入力には使えない | Apple公表仕様・各報道 |

### 公称FoVは「対角」である(検算)

XREALは軸を明記しないが、One Pro を「4mで171インチ相当」と表現する。
対角57°から求めた対角長は `2 × 4m × tan(28.5°) = 4.34m = 171.1インチ` で公称値と一致する
(One も 50° → 4mで147インチで一致)。よって**公称値は対角FoV**として扱う。
この検算は `GlassOpticsMathTests.公称FoVを対角とみなすと仮想スクリーンのインチ表記と一致する` で固定した。

対角50°・16:9 から換算すると **水平 44.2° / 垂直 25.7°**。

## 2. そこから導かれる制約

### 2-1. グラスの頭部姿勢はiOSからは取れない(回避策も無い)

- XREAL SDK は Android 専用。iOS版は存在しない。
- XREAL Air系がUSB-HIDで公開しているIMUストリームも、**iOSアプリからは触れない**
  (公開APIが無く、MFi/DriverKitの対象外)。
- したがって第1期の空間トラッキングは**iPhoneのARKitが単独で担う**。
  これは既に確定している胸マウント運用(README 2026-09-02)の前提と一致する。
- **首振りだけは AirPods で補える(2026-10-19・タスク表「首を振り向けた時に想定する場所を走る」)**。
  AirPods(Pro・第3世代以降・Max)の頭の向きは `CMHeadphoneMotionManager` で取れる。Swift が頭のヨーを
  `UpdateHeadYaw` で送り、Unity が進行方向との差(首振り)をグラスの描画の向きへ足す(`HeadYawBaseline`)。
  ヨーだけ・基準は差の長周期平均・±90°で打ち切り。準備画面で AirPods を「接続」したときだけ使う(既定OFF)。
  Bluetooth 経由なので遅延はグラス本体の IMU より大きいはず — 実機で見え方を確かめる(FIELD_TEST_PLAN §0-A 13)

### 2-2. グラスは「平面スクリーン1枚」である

映像はDP Alt Modeで送る2D映像で、両眼に同じ画が出る。
つまりUnityが描くのはステレオでも頭部追従レンダリングでもなく、
**頭に貼り付いた(あるいは空間に固定された)1枚のスクリーン**。

### 2-3. 画面モードは Follow(固定)以外に選択肢が無い

| グラスのモード | 起きること | 可否 |
|---|---|---|
| **Follow(固定)** | スクリーンが常に目の前。頭回転をグラスは補正しない | **これを使う** |
| Follow(スムーズ) | 遅れて追従するぶん見かけが揺れ、M2Pに追従ラグが乗る | 不可 |
| Anchor | グラスが自前の3DoF/6DoFでスクリーンを空間固定 | 不可(下記) |

Anchorが使えない理由は2つ。
(a) 走行中はランナー自身が前進するため、空間固定のスクリーンからは走り去ってしまう。
(b) グラスが頭回転を打ち消すので、Unity側でも頭部姿勢を適用すると**二重補正**になり、
首を振るたび映像が逆方向へ流れる。

この判断は `HeadPoseMath.ResolveOrientationSource` / `IsDoubleCompensationRisk` に
コードとして落としてある(Anchorのときは外部頭部姿勢が来ていても採用しない)。

> **運用手順**: 実機テスト前にグラス側の画面モードを Follow(固定)にすること。
> ユーザーがグラス本体のボタンで変更できるため、FIELD_TEST_PLAN の事前準備に含める。

## 3. 実装した基盤

### 3-1. グラスの光学系で描く (`GlassViewRig` + `GlassDisplayProfile`)

**直していた問題**: グラス接続中も描画はARKitカメラのままで、投影行列はiPhoneカメラの
内部パラメータ由来だった。iPhoneの画角とグラスの画角は別物なので、
3.0m前方に置いたアバターが**実寸の角度で見えていなかった**。

- グラス接続で出力カメラ(タグ無し・`Camera.main` を奪わない)を実行時生成し、
  `Camera.fieldOfView` にプロファイルの垂直画角を入れる。
- ARKitカメラは**有効なまま**(トラッキングを止めない)`cullingMask = 0` にして描画だけ譲る。
  切断で元の設定へ戻す。
- 外部ディスプレイのアスペクトが16:9でない場合は、**水平画角を正として**垂直を求め直す
  (横方向の角度スケールを実物に合わせる = 横に潰れない)。

機種の特定はiOSが知る解像度・リフレッシュレートのみが手掛かりで、
1920×1080はOne / One Pro / Air2 で共通のため分離できない。
**既定は本プロジェクトの実機である XREAL One**。Swiftが `model` を送れればそれが優先される。

### 3-2. 視点と向き (`HeadPoseMath`)

- **視点**: ARKitカメラは胸(1.2m)、グラスは目(1.55m)。差の0.35mだけ持ち上げる。
- **向き**: ARKitカメラの姿勢をそのまま使うと、胸の上下動・ロールが頭固定スクリーンに出て
  画面全体が揺れる。§4.1が禁じている酔いの原因そのものなので、
  **ヨーのみを §4.1 の移動平均済み進行方向から作る**。
- **俯角**: 狭い垂直画角にアバターを収めるため、光軸を下向きに傾ける(既定上限15°)。

将来グラスの実姿勢が供給できるようになったときのために
`UpdateGlassPose` コマンドと `GlassViewRig.SetExternalHeadPose` を通してある。
供給が0.25秒途切れれば自動で進行方向ヨーへ戻るので、欠測しても破綻しない。

### 3-3. HUDのセーフエリア (F-07)

バードバス光学系は最外周で歪み・減光が出て、アイボックスから僅かにずれると四隅から欠ける。
iPhone画面用の「隅から100px」のままでは時間・ペースが読めない位置に載るため、
グラス接続中は有効表示域を **90%** に絞る(`PeripheralHUDManager.ApplyEdgeInsetFraction`)。

### 3-4. HUDの見た目(加算表示の制約・2026-10-16〜)

グラスは光を**足して**見せる(光学シースルー)。**黒は透けて見えない** — 暗いパネル・影・黒い縁取りはグラスでは消える
(TMP の黒アウトラインもグラスでは効いていない)。面を明るく塗ると路面が見えにくくなり、電池も食う。
そのため HUD は面を塗らず、細い線・小さなラベル・数値の淡い発光で組む(`PeripheralHudSkin`):

- 左上 = TIME / DISTANCE、右上 = PACE(維持=緑・遅れ=赤)と状態(ON PACE / BEHIND)と**ペースゲージ**
  (中央の目印=目標・右=速い・左=遅い、±30秒/km で端 — `PaceHudDisplay.GaugePosition`)。中央は空、下部は F-10 の警告だけ(F-07 のまま)
- 数値は数字だけ等幅(桁が変わっても揺れない)。フォントは Inter(`Resources/Fonts/HUD-Inter_SDF`・OFL)。色はアプリのアクセント(ライム)
- **F-10 の警告(日本語)は端末のフォント**(iOS はヒラギノ)で描く。同梱の Inter / LiberationSans には日本語が無く、
  2026-10-16 まで警告は ARテンプレートの別キャンバスに載ったうえ**1文字も描かれていなかった**(E2E は「出ている」しか見ていなかった)。
  日本語フォントが無い端末では英語の文言にする。開発者モードの `hud.jaFont` で読み込めたフォントが分かる

**見た目を変えたら画像で確かめる**: `Unity.exe -batchmode -projectPath <repo> -executeMethod HudPreviewRunner.Run -logFile hud-preview.log`
(エディタでは Build → Capture HUD Preview)。`Builds/HudPreview/` に5状態(維持・遅れ・スプリット・GPS喪失・GPS待ちのHUDのみ)×2枚 —
`*_glass.png` はグラスが出す光そのもの(黒=透明)、`*_seethrough.png` は晴れたトラックに重ねた近似。

## 4. 発見した仕様上の衝突(チーム判断が要る)

**F-03の「3.0m前方」と XREAL One の画角は両立しない。**

眼高1.55m・身長1.75mのアバターを3.0m前方に置くと、足元から頭頂までが **垂直31.1°** を占める。
XREAL One の垂直画角は **25.7°** なので、**全身は入らない**。

| | XREAL One (50°) | XREAL One Pro (57°) |
|---|---|---|
| 垂直画角 | 25.7° | 29.8° |
| 3.0mでの占有角 | 31.1° | 31.1° |
| 全身が収まる最短距離 | **3.71m** | **3.16m** |
| 足元の地面が見え始める距離(俯角11.8°) | **3.38m** | 3.0m 付近 |

副作用として、**§7.2のオーラ(足元からランナー側へ放射)と接地の見えは視野に入らない**。
取り得る選択肢:

1. **足元の欠けを許容**する(腰から上だけ見える。オーラは事実上見えない)
2. **先行距離を3.7m以上へ**変更する(F-03の3.0mを仕様変更する)
3. **アバターを小さくする**(等身大でなくなる)
4. **One Pro へ機材変更**する(それでも3.2m必要)

**決定(2026-10-13 チーム判断)は 3.(大きさを譲る)。** 3.0m前方は保ち、グラスへ出力している間だけ
`GlassViewRig` が「その画角で頭から足元まで収まる身長」(`GlassOpticsMath.MaxFullBodyHeightMeters` − 余白3cm)を
`AvatarEngine.SetHeightLimitCm` で上限にする。XREAL One では **約144cm**(俯角約14.7°・地面は2.96m先から見える =
足元のオーラも視野内)、One Pro では画角が広いぶん高くなる。iPhone画面に戻ると要求どおり(175cm)。
数値は接続時にログへ出て、`GlassViewRig.FitHeightLimitCm` / `FullBodyFitsInFov` / `NearestVisibleGroundMeters` で読める。
E2Eで「収まる・足元が見える・切断で戻る」を固定している。
(2026-10-13 以前の実装は 1. 欠けを許容 だった)

## 5. 残っていること

- **グラス実機での目視確認**: 画角・俯角・HUDセーフエリアは実機でしか最終判断できない。
  `Docs/FIELD_TEST_PLAN.md` の事前準備へ「画面モード = Follow(固定)」を追加すること。
- **M2Pの実測**: グラス側X1のM2Pは約3msと公称されているが、
  本システムのM2Pは「センサー時刻 → 提示時刻」で測る(HANDOVER §レイテンシ参照)。
  グラスのスキャンアウトぶんは公称値で補える定数として扱う。
- **機種名の受け渡し**: 現状Swiftは `model` を送っていない(iOSからは判らないため)。
  UIで機種を選ばせるなら `UnityBridge.connect(model:)` に渡すだけで効く。
- **ステレオ表示**: グラスの3D Mode(サイドバイサイド)を使えば両眼視差を出せるが、
  第1期スコープ外。使うなら出力カメラを2台に増やす。
