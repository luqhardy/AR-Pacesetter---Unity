# 実地実証テスト計画書(陸上トラック)

企画書§6「成功の定義」を実地で計測するためのチェックリスト。
E2Eで自動検証済みのロジックは対象外とし、**実機・実地でしか測れない項目**に絞る。

## 0. 事前準備

- [ ] Mac統合ビルド完了(SWIFT_INTEGRATION.md ②)・iPhone実機で全画面フロー確認済み
- [ ] 権限ダイアログ確認: カメラ/位置情報/モーション/Bluetooth/ヘルスケア/マイク(初回起動時に全て許可)
- [ ] XREAL One接続でARビューがグラスへ出力されること(外部ディスプレイ対応・室内で事前確認)
- [ ] Apple Watch装着+ワークアウト開始(HealthKitへ心拍が流れる状態)
- [ ] iPhoneバッテリー80%以上・グラスのUSB-C給電経路の確認
- [ ] 荒天中止基準: 降雨(グラス非防水)・気温31℃以上は中止または短縮(疲労補正2.0×領域)

## 1. 計測項目(成功基準→計測方法)

| # | 成功基準(企画書§6) | 計測方法 | 合格ライン | 記録先 |
|---|---|---|---|---|
| T1 | コーナー追従の安定性 | 400mトラック2周。曲線部でアバターの不自然な挙動/ワープの有無を並走者が目視+iPhone画面録画 | ワープ0回・接線維持 | 画面録画+チェック表 |
| T2 | Motion-to-Photon ≤20ms 95% | 走行中の`LatencyReport`(1Hz)をSwift側でログ。走行後に95パーセンタイル算出 | p95 ≤ 20ms | ログCSV |
| T3 | 接地精度 | 直線・コーナー・(あれば)緩傾斜でアバターの足元の浮き/めり込みを目視評価(3段階) | 全区間で「浮きなし」 | チェック表 |
| T4 | GPS精度と距離計測 | トラック既知距離(400m/周)とアプリ計測距離の誤差 | 誤差 < 3% | 統計画面のスクショ |
| T5 | 視覚的安定性(酔い) | 20分連続走行後の主観アンケート(SSQ簡易版: 酔い/眼精疲労/没入感 各5段階) | 酔い ≤ 2 | アンケート |
| T6 | 一連のシークエンス完遂 | 起動→接続→設定→走行→ゴール→統計→再走行(ゴースト)をシステムダウンなしで | クラッシュ0 | チェック表 |
| T7 | GPS喪失復帰(実地) | スタンド下・建物影を通過し、慣性→フェード→復帰演出の動作確認 | FSM通り遷移 | 画面録画 |
| T8 | 音響の実用性 | 足音/呼吸音の聞こえ方(交通騒音下含む)・環境適応音量の効き | 主観3段階で2以上 | チェック表 |
| T9 | バックグラウンド計測 | 走行中に画面ロック1分→復帰。距離・タイムの連続性確認 | 欠落なし | 統計画面 |

## 2. 当日の実施手順

1. **セットアップ(15分)**: 機材接続 → Readyチェック全緑 → 静止状態でアバター表示確認
2. **キャリブレーション走(1周・ゆっくり)**: T3接地・T5初期感覚の確認。問題があればここで中断判断
3. **本計測(2〜3周・設定ペース走)**: T1/T2/T4を計測。並走者はコーナーでの挙動を録画
4. **シナリオ試験**: T7(建物影)→ 一時停止→再開 → T9(画面ロック)
5. **ゴール→統計確認 → ゴースト再走(1周)**: T6完遂判定
6. **クールダウン+アンケート(T5/T8)**

## 4. 中断基準

- 転倒・接触の危険を感じた時点で即中断(KPI: 重大事故ゼロが最優先)
- アバターの異常挙動(ワープ・視界の大きな揺れ)が続く場合は装着を外して原因記録
- iPhone発熱によるスロットリング(レイテンシ急増)時は休止
